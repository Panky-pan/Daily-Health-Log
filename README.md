# Daily-Health-Log ·「每日健康打卡」

> 一个只服务自己的极简健康打卡网页：每天花 1 分钟记录运动、饮食、体重和饮水，坚持情况一屏看清，目标没达成时页面内提醒。

## 这是什么

市面上的健康 App 多为「泛人群」设计，功能重、广告多、数据在别人服务器上。这个项目走相反的路：**轻量、无账号、无广告、数据存在自己的云端数据库里**，只做四件事——记录、坚持、趋势、目标提醒。

项目从零基础起步，按 28 天计划一天一小步推进，边做边学。

## 已实现的功能（MVP）

| 编号 | 功能 | 一句话说明 |
|---|---|---|
| F1 | 目标设置 | 首次打开填「每日运动分钟数」「每日饮水量」，之后可随时改 |
| F2 | 今日打卡 | 运动类型 + 时长、三餐（一句话 + 健康/普通/放纵标签）、体重、饮水；卡路里自动估算，不手填 |
| F3 | 打卡日历与坚持率 | 当月日历标记打卡日，显示当前 streak、历史最长连续天数、当月坚持率，可点开单日详情 |
| F4 | 趋势图表 | 体重折线图 + 每周运动时长柱状图 |
| F5 | 目标提醒条 | 页内黄色提醒条写清差多少，达标变绿，不弹窗不推送 |

页面结构（共五页）：① 开屏页 `welcome.html`（站点入口）② 今日页 `index.html`（今日目标、打卡入口、连续天数、饮食健康分）③ 打卡页 `checkin.html`（记录表单，保存后自动回今日页）④ 历史记录页 ⑤ 趋势页。

## 技术方案

**路线 A：现行版本（静态页面 + 云端数据）**

- 原生 HTML + CSS + JavaScript，不用任何框架
- 页面部署在腾讯云 CloudBase 静态托管；数据存在 CloudBase 的 PostgreSQL 数据库（`checkins` / `settings` 两张表）
- 接口由一个 HTTP 型云函数（`api-health`）提供；本机 `localStorage` 只作缓存和断网兜底（key 以 `dhl:` 前缀隔离）
- 无账号体系（登录属路线 B）

**路线 B：二期蓝图（账号体系，仅设计未动工）**

- 云端同步与数据库**已提前做完**（原计划等 MVP 上线满一个月，现已先上线）
- 待做的是**登录**：接入 CloudBase 身份后，网页改用登录身份访问接口，同时把现在匿名的 `anon` 权限降为只读——**顺序不能反**，先收权限会连自己的网页一起锁死
- 前端是否换 React + Vite 待定；数据结构已按云端字段名对齐，迁移不做返工

技术选型的完整对比与取舍理由见 `TECH_DESIGN.md`。

## 数据与隐私

- 打卡数据存在**你自己的 CloudBase 数据库**里（PostgreSQL，两张表），不上传第三方、不做用户画像、不用于任何推荐
- 无账号、无注册、无第三方统计与追踪
- **当前限制（须知）**：还没做登录，所以**只要拿到网址的人都能打开并看到这份数据**（技术上也能改）。**链接不要公开发布**；已排期的登录功能会解决这个问题
- 附带风险：断网时新记的数据会先存在本机，页脚会提示「已存本机」，等能连上时自动同步上去
- 仓库内不含任何密钥：`.env`、`*.pem`、`*.key`、本地数据库文件已通过 `.gitignore` 全部排除；数据库凭证由云平台注入环境变量，不写进代码

## 明确不做

食物数据库 / 拍照识餐、社区与分享、智能训练计划、饮食推荐、消息推送、会员付费、广告，以及 MVP 阶段的任何账号体系。
